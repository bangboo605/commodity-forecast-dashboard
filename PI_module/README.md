# PI — 예측 분위수와 통합성적표 만들기

분기 시계열 CSV 한 개와 첫 origin 날짜를 넣으면 모델을 자동으로 고르고, 모든 origin의 **예측 분위수(딕셔너리 1)** 와 **통합성적표(딕셔너리 2)** 를 만들어 줍니다. 이 폴더만 있으면 실행됩니다.

## 폴더와 파일

```
PI_module/
├─ PI.py          실행 파일(명령줄과 함수 겸용)  ← 사용자는 PI.py 또는 PI.ipynb 중 하나만 실행
├─ PI.ipynb       같은 일을 셀 단위로 (▶ 작동 코드 셀만 실행해도 결과가 나옴, ▷ 설명 코드 셀은 확인용)
├─ selection.py   모든 조합 백테스트와 모델 선정 (model_selection/ 복사본, 직접 실행하지 않음)
├─ ts_models.py   AR 단독, GARCH, SV 모델 계산 (model_selection/ 복사본, 직접 실행하지 않음)
├─ test_PI.py     테스트
├─ data/          입력 CSV
├─ cache/         계산 캐시 (실행하면 생김)
└─ output/        결과
```

- `PI.py`와 `PI.ipynb`는 같은 폴더에 같은 이름의 결과를 저장하므로, 같은 입력으로 나중에 실행한 쪽이 덮어씁니다.

## 빠른 시작

```
python PI.py <CSV 이름> <첫 origin의 마지막 분기 날짜>
python PI.py X1_l1 '2019-12-01'
```

- 노트북으로 하려면 `PI.ipynb`에서 `csv_name`, `first_insample_end_date` 두 셀만 바꾸고 위에서 아래로 실행합니다.
- CSV는 이름만 주면 현재 폴더, `data/` 순으로 찾습니다(`.csv` 생략 가능).
- 첫 실행은 변수 하나에 2~5분 걸립니다. 같은 입력으로 다시 실행하면 캐시(`cache/`)를 읽어 바로 끝납니다.
- 파이썬에서는 `from PI import run_pi; d1, d2 = run_pi("X1_l1", "2019-12-01")`.
- **Python 3.13 필수** (3.12 이하, 3.14 이상은 지원하지 않음). `python --version`으로 확인하세요.
- 필요한 패키지: numpy, pandas, scipy, statsmodels, arch, pmdarima, properscoring (`pip install -r requirements.txt` 또는 `uv sync`).

## 입력

**CSV**: `Date`, `Data` 두 열, 연속된 분기 자료.

```
Date,Data
2011-06-01,70.10
2011-09-01,-220.88
```

- `Date`는 그 날짜가 속한 분기로 읽습니다(2018-12-01 → 2018-Q4).
- 최소 28분기가 필요합니다. 맨 앞뒤의 빈 행은 자동으로 잘라 냅니다.
- 값이 모두 양수일 때만 로그 스케일도 후보가 됩니다.

**첫 origin 날짜**: 이 날짜가 속한 분기까지를 훈련 데이터로 쓰는 것이 첫 origin이고, 이후 데이터 끝까지 한 분기씩 origin이 이어집니다.

- 가장 이른 분기는 데이터의 24번째 분기, 가장 늦은 분기는 끝에서 5번째 분기입니다.
- 이른 날짜는 보정 구간이 짧아 구간이 불안정합니다. 첫 origin이 훈련 30분기 이후(보정 10개 이상)인 것을 권합니다.

**입력에 문제가 있으면** 계산을 시작하기 전에 원인과 위치를 알려 주는 오류로 멈춥니다. 이때 `cache/`와 `output/`은 건드리지 않습니다. 메시지에 나온 대로 고치면 됩니다. (`test_PI.py`가 아래 경우를 모두 확인합니다.)

| 구분 | 시나리오 | 메시지의 핵심 | 고치는 법 |
|---|---|---|---|
| 파일 | CSV 이름이 틀림 | `CSV를 찾지 못했다` | 이름과 `data/` 위치 확인 |
| 열 | `Date` 또는 `Data` 열이 없음 | `Date, Data 두 열이 있어야 한다` (있는 열도 알려 줌) | 열 이름을 `Date`, `Data`로 |
| 값 | 숫자가 아닌 값 (예: `abc`) | `Data에 숫자가 아닌 값이 있다 (Date …)` | 표시된 날짜의 값을 숫자로 |
| 값 | 가운데에 빈 값 | `Data의 가운데에 빈 값이 있다 (Date …)` | 값을 채우기 (맨 앞뒤 빈 행은 자동으로 잘라 냄) |
| 값 | 값이 하나도 없음 | `Data에 값이 없다` | 값이 든 CSV인지 확인 |
| 값 | 모든 값이 같음 | `Data 값이 모두 같아서 …` | 변하는 시계열을 넣기 |
| 값 | 28분기 미만 | `데이터가 너무 짧다 … 최소 28분기` | 28분기 이상의 자료 |
| 날짜 | 날짜로 읽을 수 없음 | `Date를 날짜로 읽지 못했다` | `2018-12-01` 같은 형식으로 |
| 날짜 | 분기가 빠짐, 중복, 내림차순 | `Date가 오름차순으로 연속된 분기가 아니다` | 빠진 분기는 행과 값을 채우고, 중복은 하나만 남기고, 오름차순으로 정렬 |
| 첫 origin | 날짜 형식이 틀림 | `첫 origin 날짜를 읽지 못했다` | `2019-12-01`, `2019Q4`, `2019/12/01`, `20191201` 중 하나로 |
| 첫 origin | 데이터 시작 이전 또는 끝 이후 | `첫 origin의 분기 …가 데이터(…)에 없다` | 데이터 기간 안의 날짜 |
| 첫 origin | 너무 이름 | `첫 origin이 너무 이르다 … 이후여야 한다` | 메시지의 분기 이후로 |
| 첫 origin | 너무 늦음 | `첫 origin 뒤에 정답이 4분기 이상 있어야 …` | 끝에서 5번째 분기 이전으로 |
| 명령줄 | 인자 개수가 틀림 | `사용법: python PI.py …` | CSV 이름과 날짜를 함께 |

## 출력

`output/<이름>/`에 변수마다 폴더가 생기고 파일 4개가 저장됩니다.

| 파일 | 내용 |
|---|---|
| `<이름>_forecast.json` | 딕셔너리 1. `json.load`로 읽으면 딕셔너리가 그대로 나옵니다. |
| `<이름>_score.json` | 딕셔너리 2 |
| `<이름>_forecast.csv` | 딕셔너리 1을 펼친 표. 열: `origin, h, 예측 분기, p5 ~ p95` |
| `<이름>_score.csv` | 딕셔너리 2 |

**딕셔너리 1** — 예측 분위수

```python
d1["2018-Q4"]    # 9 x 4 배열
# 행: 5, 10, 20, 30, 50, 70, 80, 90, 95% 분위수 / 열: h1 ~ h4 (원래 단위)
```

- **key는 훈련에 쓴 마지막 분기**(origin)이고, 열은 **그다음 4분기**입니다. 위 예에서 열 h1~h4는 2019-Q1, Q2, Q3, Q4의 예측이며 2018-Q4 자체는 들어 있지 않습니다.
- 첫 origin부터 데이터 끝까지 모든 origin이 들어 있습니다. 마지막 origin은 데이터 끝 이후 4분기를 예측한 값입니다(정답 없음).
- CSV의 `예측 분기`는 `2019Q1`처럼 하이픈 없이 쓰고, key는 `2018-Q4`처럼 하이픈이 있습니다.

**딕셔너리 2** — 통합성적표 `{'mae', 'mse', 'crps', 'coverage'}`

- 4분기 정답이 모두 있는 origin의 평균입니다.
- `mae`, `mse`, `crps`는 전체 표준편차로 정규화한 값(mae는 |실제 − 점예측| ÷ 표준편차, mse는 그 제곱)이고, `coverage`는 90% 구간(5~95%) 적중률(%)입니다.

화면 출력 예:

```
선정 모델: GARCH (d=0, D=0) 원 스케일, 리샘플링 구간 | 후보 6/24개, 보정 origin 15개
딕셔너리 2: {'mae': 1.0214, 'mse': 1.5448, 'crps': 0.7453, 'coverage': 82.1429}
```

## 작동 방식

```
CSV ─▶ 입력 검사 ─▶ 모든 조합 백테스트 ─▶ 모델 선정 ─▶ 선정 조합으로 분위수 계산 ─▶ 딕셔너리 1·2 저장
```

1. **백테스트**: 모델 3종(AR 단독, GARCH(1,1), SV) × 차분 (d, D) 4가지 × 스케일(원, 로그) × 구간 방식(자체, 리샘플링)을 origin마다 한 분기씩 늘려 가며 적합하고 h=1~4를 예측합니다. 훈련 구간만 쓰므로 미래 정보는 들어가지 않습니다.
2. **선정**: CRPS 1등의 ±10% 이내 후보 중 커버리지가 90%에 가장 가까운 조합을 고릅니다.
3. **분위수**: 선정 조합 하나를 같은 시드(42)로 다시 계산해 origin마다 9개 분위수를 만듭니다. 같은 입력이면 같은 결과가 나옵니다.
4. **캐시**: 1번의 결과를 `cache/`에 저장합니다. CSV에 새 분기를 덧붙이면 바뀐 부분 뒤쪽만 다시 계산하고, 첫 origin 날짜를 바꾸면 새로 계산합니다.

## 데이터를 고치거나 늘렸을 때

CSV(`data/`)를 고치거나 새 분기를 덧붙여 다시 실행하면 아래 순서로 코드가 돕니다. 실행할 때마다 CSV를 새로 읽고, 캐시에 **그때 쓴 분기와 값이 함께 저장**되어 있어서 그것과 비교합니다(`output/`의 결과 파일은 비교에 쓰지 않습니다).

| 순서 | 하는 일 | 코드 |
|---|---|---|
| 1 | 시작: 인자(CSV 이름, 날짜)를 받고 `run_pi` 호출 | `PI.py:147-152` |
| 2 | CSV 읽기와 형식 검사: 파일, 열, 날짜, 숫자, 빈 값, 분기 연속성 | `read_series` `PI.py:37-71` |
| 3 | 길이와 첫 origin 검사, 보정 구간 길이 계산 | `prepare` `PI.py:74-95` |
| 4 | 캐시 파일 이름 결정: 변수 이름 + 설정(첫 origin 날짜 포함) + 시드 + 버전 | `_cache_path` `selection.py:110-115` |
| 5 | 캐시가 있으면 이전 데이터와 비교해 처음 달라지는 분기 찾기 | `_first_diff` `selection.py:118-122` |
| 6 | 같으면 캐시를 그대로 읽고, 다르면 영향받는 origin부터 뒤쪽만 이어서 계산하고, 캐시가 없으면 전체 계산한 뒤 캐시 저장 | `run_grid` `selection.py:133-153` |
| 7 | 모델 선정 (CRPS ±10% 중 커버리지 90%에 가까운 것) | `select_model` `PI.py:98-106`, `select` `selection.py:163` |
| 8 | 선정 조합만 캐시 없이 다시 계산해 분위수 만들기 (딕셔너리 1) | `forecast_dict` `PI.py:108-118` |
| 9 | 성적표 만들기 (딕셔너리 2) | `score_dict` `PI.py:121-124` |
| 10 | `output/<이름>/`에 파일 4개를 덮어쓰기 | `PI.py:154-158` |

- 2, 3번에서 오류가 나면 4번 이후는 실행되지 않아 캐시와 `output/`은 그대로입니다.
- 4번에서 이름이 달라지면(첫 origin 날짜, 이름, 시드, 버전이 바뀜) 이전 캐시를 열지 않고 처음부터 계산합니다.
- 6번의 처리 결과: 같으면 계산 없음, 새 분기가 붙거나 중간 값이 바뀌면 그 분기의 영향을 받는 origin부터만 다시 계산(처음부터 계산한 결과와 같음), 캐시가 없으면 전체 계산(2~5분).
- 캐시는 라이브러리 버전과 코드 변경을 감지하지 못합니다. 모델 계산 코드를 고치면 `selection.py`의 `CACHE_VERSION`을 올리고, 의심스러우면 `cache/`의 해당 파일을 지우고 다시 실행하세요.
- `PI.ipynb`는 `PI.py`와 같은 `selection.py`를 쓰므로 4~6번이 똑같이 동작하고, 2~3번의 검사는 [1], [3] 셀에 같은 내용이 들어 있습니다.

## 테스트

```
python test_PI.py          # 빠른 테스트 28개 (캐시를 써서 금방 끝남)
python test_PI.py full     # + 변수별 날짜 8개, 새로 계산해서 30분 안팎 (총 36개)
```

마지막 줄에 `실패 0개`가 나오면 정상입니다. 평소에는 빠른 테스트면 충분하고, `full`은 모델 계산 코드를 크게 고쳤을 때만 돌립니다.

## 알아 둘 점

- 모델 선정과 성적 평가가 같은 구간(첫 origin 이후)이라 점수가 다소 낙관적일 수 있습니다.
- horizon은 h=1~4로 고정입니다.
