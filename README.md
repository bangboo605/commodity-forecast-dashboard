# 원자재 가격 예측 시나리오 대시보드

시계열 모델로 만든 **주요 변수의 예측값**을 high·base·low 시나리오로 제시하고, 그 시나리오로 계산한 **가격 전망**을 Streamlit 대시보드에서 비교·시각화하는 프로젝트입니다. 변수마다 가장 알맞은 예측 모델을 백테스트로 고르는 과정(모델 선정)과, 그 결과를 앱에서 보여 주는 과정(시각화)까지를 한 저장소에 담았습니다.

> 공개를 위해 금 주요 변수 6개의 이름은 `X1`~`X6`으로 비식별화했습니다. 데이터 값과 분석 결과는 그대로입니다.

## 라이브러리 설치

Python 3.13이 필요합니다. 아래 세 가지 중 **하나만** 골라 설치하면 됩니다. 세 파일 모두 같은 목록입니다.

## 대시보드가 하는 일

- **품목 선택**: 알루미늄, 전기동, 금, 은
- **주요 변수 시나리오**: 예측시점을 고르면 변수별 high·base·low 값이 분기별로 표시됩니다. 값을 가져오거나 직접 입력해 `final` 시나리오를 확정(commit)할 수 있고, ±10% 일괄 조정도 가능합니다.
- **가격 전망**: 확정한 시나리오로 가격을 계산해 과거 실제가와 함께 그래프로 보여 줍니다. 금은 시변계수(TVP) 회귀로 예측시점마다 다시 학습해 계산합니다.
- **결과 비교**: 결과를 데이터셋으로 저장해 여러 시나리오를 겹쳐 비교합니다. 예측시점을 바꿔 가며 과거 실제가와 비교하는 백테스트도 지원합니다.

앱은 예측 모델을 직접 돌리지 않고, `model_selection/`이 만든 시나리오 CSV(`data/gold/..._forecast_model.csv`)를 읽어 보여 줍니다. 모델 계산과 화면을 분리해 둔 구조입니다.

## 예측값은 어떻게 만들었나

변수마다 다른 모델이 알맞을 수 있어서, 후보를 모두 같은 조건으로 백테스트해 고르는 방식으로 만들었습니다.

- **후보**: 모델 3종(AR 단독, GARCH(1,1), SV) × 차분 (d, D) 4가지 × 스케일(원, 로그) × 예측구간 방식(모델 자체 구간, 오차 리샘플링)
- **평가**: 확장 윈도우 walk-forward, 1~4분기 앞 예측. 지표는 CRPS, MSE, 90% 구간 커버리지
- **선정 규칙**: CRPS 1등의 ±10% 이내 후보 중 커버리지가 90%에 가장 가까운 것
- **미래 정보 차단**: 모델 적합, 오차 표본, 단위 상수 모두 각 예측시점 이전 데이터만 사용
- **재현성**: 리샘플링 난수 시드를 42 하나로 고정해 변수와 모델이 같은 난수로 비교되게 했습니다.
- **증분 계산**: 새 데이터가 들어오면 바뀐 시점 뒤쪽만 다시 계산합니다. 변수 2개, 시나리오 6가지에서 증분 결과가 처음부터 계산한 결과와 같음을 확인했습니다(`notebooks/14`의 증분 계산 확인).

## 분석 흐름 (노트북 번호 순)

번호 순서대로 읽으면 판단이 바뀐 과정까지 볼 수 있습니다. 초반 시리즈는 탐색 기록이라 이후에 결론이 바뀐 것도 있습니다.

| 시리즈 | 다룬 것 |
|---|---|
| 0 ~ 2 | 초기 예측 모델(TVP 백테스트), 훈련 기간 비교, 변수별 모델 후보 설계와 예측구간 커버리지 튜닝 |
| 3 ~ 5 | 로그 변환 없이 다시 검증(순위가 뒤집힘), 계절 차분 검증, 변수별 모델 선택(AutoML 방식) |
| 6 ~ 7 | 평가 파이프라인 모듈화, 평가 지표를 7분위 CRPS·커버리지·MSE로 교체, bootstrap의 시계열 타당성 검증 |
| 8 ~ 9 | ARIMA·GARCH·SV 동시최적화, 리샘플링 구간과 자체 구간 비교, 원 스케일과 로그 스케일 비교 |
| 10 ~ 11 | CRPS 계산 방식 비교, 데이터 계절성 확인, 리샘플링 오차 표본 수정, 선정 기준 비교, 구간 폭 보정(도입하지 않음) |
| 12 ~ 13 | 주요 변수 6개로 일반화(차분 후보 판정, 모델 비교, 변수별 선정, 계절성 점검), 선정 모델의 예측구간 그림 |
| 14 | 금 가격에 적용: 선정 모델과 TVP 모델 비교, 주요 변수 예측으로 만든 가격 전망, 시드 민감도, 증분 계산 확인 |

**중간에 판단이 바뀐 곳**
- 모델 선정 기준을 "커버리지 최대"에서 "90%에 가장 가까운 것"으로 바꿨습니다(구간이 넓은 조합이 유리해지는 문제).
- 로그 변환 없이 다시 검증하자 회귀의 우위가 사라지고 Auto-ARIMA가 1위가 됐습니다(3시리즈).
- 평가 단위 상수가 전체 표준편차를 써서 미래 정보가 섞이던 것을, 각 시점 이전 데이터의 표준편차로 고쳤습니다(12시리즈).
- 구간 폭 보정(scale k)과 로그 점예측 보정(smearing)은 검증한 뒤 도입하지 않기로 했습니다(smearing은 선정된 구조에서 MSE가 오히려 나빠졌습니다).
- 난수 시드를 변수마다 다르게 두던 것을 하나로 고정했고, 그 결과 선정이 한 변수에서 바뀌었습니다(두 후보가 거의 동점이었음).

## 실행

```powershell
streamlit run item_selection_v3.8.py
```

환경은 `pyproject.toml`과 `uv.lock`(Python 3.13)을 기준으로 재현합니다. 분석 노트북과 `model_selection/`은 앱 의존성 외에 `arch`, `pmdarima`, `properscoring`, `scipy`, `scikit-learn`이 필요합니다.

```powershell
python -m model_selection.build_scenarios       # 변수별 모델 선정 + 시나리오 CSV 생성
```

## 한계

- 표본이 60분기 안팎이라 단위근·계절성 검정의 검정력이 낮고, 후보 간 차이가 작은 경우 선정이 불안정합니다(시드 민감도 노트북 참고).
- 차분 차수(d)를 전체 데이터로 정했기 때문에 일부 변수의 백테스트가 낙관적일 수 있습니다.
- 발표 시차와 데이터 개정은 반영하지 않았고, 예측 horizon은 1~4분기로 고정했습니다.
- 변수 비식별화로 일부 노트북의 그림은 같은 코드로 다시 그린 것이며, 일부 본문 숫자는 난수 시드 차이로 소수점 아래가 원본과 조금 다를 수 있습니다.
